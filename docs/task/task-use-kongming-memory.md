# 军机阁接入孔明记忆插件

> 功能定义：[军机阁技术设计 §4.3](../tech-design.md#43-per-agent-记忆)
> 比较基线：军机阁 `adb45c3`，孔明 `e83cd41` 加已有往来卡片工作区改动

## ① 需求与变更

用 `@kmh/kongming-memory-v1` 替换军机阁复制的记忆逻辑。大臣继续使用原会话及 `agent-team/<agentId>/MEMORY.md`、`MEMORY.frozen.md`。两边的默认提醒与追加工具共用一套定义。保留每个大臣的旧文件、冻结发布与档案生命周期。

## ② 精简技术设计

记忆插件提供按文件目录绑定的工厂。孔明原有宿主接入负责将孔明会话绑定到其既有目录。军机阁运行时只给共享工厂提供大臣的目录和模板选项。独立发行包在打包时从记忆插件源构建产物引入实现。旧提醒来源仍可读，以兼容进行中的轮次及历史显示。

## ③ 测试用例与变化

- T1 新增。两个旧档案恢复后，各 Agent 请求只读到自己的冻结正文，甲追加时乙的双文件字节保持原样。
- T2 新增。真实执行循环验证成员只收到一次默认提醒、工具有成功回执、旧条目保留。普通会话零提醒且无工具。同轮已有旧军机阁提醒时也只消费一次。
- T3 沿用。复用孔明记忆的冻结、手动压缩及工具作用域测试，回归军机阁删除和委派。军机阁旧私有文件测试退役，初始化、文件回退及发布由共享测试覆盖。
- T4 新增。编译后检查发行包入口可加载、旧目录已移除、孔明默认文案延续原初始安装值。随后在 60080 核对新版运行。

## ④ 技术实现

军机阁 [bindMemory](../../packages/kmh-junji/src/runtime.ts#L324) 从成员档案的目录构造两个文件路径，将原会话绑定到共享服务。删除原 `src/memory` 八个文件。共享包沿用孔明的文件队列、冻结发布、追加工具与手动压缩实现，并把原安装文案变成两边共用的默认配置。构建从相邻孔明源码解出共享入口并内置到发行包，运行时复用宿主 DSH。军机阁的记忆模板仍支持独立覆盖。

## ⑤ 验证结果

53 个自动化用例通过，构建、发行包和文案对齐通过。60080 当前是旧版，待沙盒加载新版并验收；军机阁 lint 入口缺少 ESLint。详见[测试报告](../../reports/use-kongming-memory/01/test-report.md)。
