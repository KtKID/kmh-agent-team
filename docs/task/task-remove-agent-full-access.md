# 孔明完全权限下删除军机阁成员

> 功能文档 [军机阁技术设计 §4.1](../tech-design.md#41-agent-注册表registry)
> 创建 2026-11-14
> 状态 构建与回归通过，KMH Web 60000 已重启

## ① 需求与变更

本轮用户要求 `junji_remove_agent` 支持完全放权。修改前的删除工具与包说明见 `f42f0ba`，技术设计已有独立的军机阁图标差异。本次修改 §4.1 孔明联动的授权条件，归档和历史保留沿用 [删除大臣任务](task-remove-agent-archive.md)。[变更记录](../tech-design.md#变更记录)。

## ② 精简技术设计

D1 读取孔明会话在 DSH 中的有效访问模式及审批策略。当访问模式为 `danger-full-access` 且审批策略为 `never` 时跳过单次审批，其他情况调用同一个审批服务并检查 `allowed-once`。审批策略优先读会话覆盖，再读宿主默认。删除前校验取消信号，复用 `runtime.remove` 的档案及归档路径。

涉及 `kongming-integration.ts`、对应测试及 DSH 类型依赖声明。授权的事实源是宿主的审批服务和访问策略服务。测试从已注册工具的入口调用。

## ③ 测试用例与变化

扩展现有孔明工具挂载测试，从注册的工具入口执行，检查审批调用、删除调用和返回值。复跑真实宿主的删除及归档回归。

| 用例 | 变化 | 预期 |
| --- | --- | --- |
| T1 | 新增 | 完全权限下跳过审批，按已核对的档案执行删除。会话覆盖及宿主默认两种来源都适用。 |
| T2 | 新增 | 完整访问与询问策略并存，或采用常规工作区权限时，单次批准才放行。 |
| T3 | 新增 | 仅关闭询问、审批服务缺失、拒绝、取消或不可用时，删除调用保持为零。 |
| T4 | 新增 | 等待审批时收到取消，即使拿到单次批准也不删除。 |
| T5 | 回归 | 挂载和发送链路、真实会话的中断与归档、档案保留和重试。 |
| T6 | 新增 | 隔离 DSH 宿主中，孔明会话从工作区模式切到完全权限后删除成员并保留归档会话。 |

## ④ 技术实现

- `packages/kmh-junji/src/kongming-integration.ts` 的 `junji_remove_agent` 回调读取会话权限，通过后调用现有删除流程。
- `packages/kmh-junji/test/` 新增审批矩阵和隔离 DSH 宿主回归。
- 包清单、锁文件与 `scripts/link-dsh.mjs` 同步可选的 DSH 访问策略依赖。包说明和技术设计同步删除规则。
